# AGENTS.md

This file provides guidance to AI coding agents (Claude Code and others) when working with code in this repository.

Chillzone — аддон для **WoW: Forever** (клиенты Classic: Lua 5.1), связывающий гильдии, добавленные текущим главой «Чиллзон» в объединение: общий чат на три уровня, перепись гильдий, «Королевство», круги на карте. Состав хранится в `security.union` и подписывается только главой главной гильдии; совпадение названия не даёт членства. Управление на вкладке `UnionPane.lua` доступно только ему, офицеры гильдий вне объединения видят на ней запрос связи, а передача главы передаёт управление без привязки к имени основателя. Имя главы в `C.MAIN_GUILD_LEADER` — только адрес запроса связи с этой вкладки; после смены главы его нужно обновить. Комментарии, документация, строки интерфейса и сообщения коммитов — на русском (коммиты в стиле `Chillzone: что сделано`); идентификаторы в коде — английские.

## Команды

```bash
luajit tests/run.lua   # все тесты, пара секунд; ненулевой код выхода при падении
luacheck .             # линтер, настройки в .luacheckrc
```

На Windows: `scoop install luajit luacheck`. Чтобы прогнать не всё, задайте `CZ_TEST_FILTER=<часть имени теста>` (сравнивается подстрока имени из `T.test`); `CZ_TEST_PROGRESS=1` печатает каждый пройденный тест. `CZ_SEED=<n>` меняет seed симулятора в `test_relay` и `test_chat`. CI (`.github/workflows/ci.yml`) запускает обе команды на каждый PR и пуш в `main`.

Сборки нет: игра грузит папку `Chillzone/` как есть. `main` защищена: любые изменения, включая повышение версии, проходят через PR с успешными `Luacheck`, `Tests (lua5.1)` и `Tests (luajit)`. Версия записана в **двух** местах: `## Version` в `Chillzone/Chillzone.toc` и `C.VERSION` в `Chillzone/Config.lua`. Тест следит, чтобы они совпадали. Для релиза сначала слить PR с версией, подтянуть `main` и только затем поставить и отправить тег `vX.Y.Z`. Workflow `release.yml` прогоняет проверки, сверяет тег с версией, собирает `Chillzone-X.Y.Z.zip` и создаёт черновик релиза (либо прикладывает архив к существующему). Публиковать после успешного workflow, проверки архива и заполнения описания. Подробный порядок — в [docs/DETAILS.md](docs/DETAILS.md#выпуск-версии).

## Устройство

**Загрузка.** Порядок файлов в `Chillzone.toc` — это порядок загрузки. Каждый файл начинается с `local ADDON, ns = ...` и кладёт свой модуль в общую таблицу (`ns.Util`, `ns.Config`, `ns.Codec`, `ns.Comm`, …). Новый файл нужно вписать в toc: тесты грузят аддон по нему. В глобальное окружение аддон пишет только `ChillzoneDB` (SavedVariables), `SLASH_CHILLZONE*` и `SlashCmdList`. Симулятор ловит утечки (`Client:Leaks`), а luacheck не пропускает запись в другие глобалы.

**Ядро (`Core.lua`).** Внутренняя шина `ns.On`/`ns.Fire` (например, событие `CHAT` для окна) и события игры через `ns.RegisterEvent`. Таймеры — `ns.After`/`ns.Every`, подкоманды — `ns.Command`, их разбор — `ns.RunCommand`, строки для `/chillzone status` — `ns.Status`. `/chillzone` принимает только команды. `/cz`, `/чз` и `/чиллзон` по Enter выполняют известную команду, остальной текст отправляют в общий чат. `/cz1`–`/cz3` и `/чз1`–`/чз3` отправляют любой текст в соответствующий канал. Пустая команда по Enter открывает окно нужного канала без подсказки в чате. Набор текста и пробел после команды окно не открывают. Ошибки перехватывает `ns.SafeCall`, их видно на вкладке «Отладка». Время для сравнения между клиентами — `ns.ServerTime()`, локальное — `ns.Now()`.

**Слои.**
- Чистые модули без вызовов игры при загрузке: `Util.lua` (регистр кириллицы — `string.lower` в игре трогает только ASCII; правило «своей» гильдии; имена Forever) и `Codec.lua` (формат всех сообщений, описан в шапке файла). Их тестировать проще всего.
- Транспорт `Comm.lua`: очередь отправки, нарезка на куски по 255 байт и сборка, разбор входящих по типу (`ns.Comm.On("Q1", fn)`).
- Логика: `Census` (приветствия H1, выбор репортёра, отчёты), `Roster` (свой ростер → отчёт), `Data` (хранилище отчётов, ранги чужих гильдий, сводки), `Relay` (ретрансляторы), `Security` (ключи, сертификаты, корни доверия, подписанные пакеты S1; см. `docs/SECURITY.md`), `Chat` (общий чат), `GuildChat` (чат своей гильдии из событий игры), `GuildBridge` (импорт обычного `/ги` в общий канал A и передача между выбранными репортёрами), `Zones` (зона → `m<uiMapID>`), `Update` (версии новее своей из H1 и последнего поля R1; два игрока — предупреждение об устаревшем аддоне).
- Вступление: `Who` (штатный `/who`, диапазоны уровней при лимите 50 строк), `Recruit` (прямые WHISPER J1/J2/J3, заявки и явный текст письма JT), `RecruitSync` (общая очередь офицеров: запрос JQ по GUILD, заявки JS и решения JX адресно по WHISPER), `RecruitPane` (экран новичка, собственное окно письма, отдельная вкладка «Заявки», число заявок — в подсказке). Контакты из подсказки сверяются с локальным `/who`; заявка не даёт доступа к подписанной сети. Общая очередь и вкладка «Заявки» доступны только офицерам по свежему ростеру; входящие рядового уходят офицерам, своей вкладки у него нет. Текст для общей очереди берётся только из JT, не из обычных шёпотов. Приглашать можно только из щелчка с игровым правом `CanGuildInvite`. Стандартные popup для письма не используем из-за taint на Forever.
- Отрисовка: `Views.lua` готовит строки и данные, а рисуют их `UI.lua` (окно и вкладки), `ChatPane.lua`, `CensusPane.lua` и `Debug.lua`. Круги на карте мира — `Map.lua` через HereBeDragons-Pins.

**Главное ограничение платформы.** На Forever аддон-сообщения в пользовательском канале не доставляются, доставляются только GUILD и WHISPER. Подписанные чат и перепись идут между гильдиями шёпотом через реле: автор → реле (`RL`) → репортёр каждой гильдии (`RM`) → его гильдия по GUILD (`RG`). В каждой гильдии все клиенты одинаково и детерминированно выбирают одного репортёра. Прямая строка общего чата уходит двумя путями: `M1` по GUILD своей гильдии и через реле остальным. Дубли отбрасывает `Chat.Receive`. Импорт `/ги` использует отдельный обмен между выбранными репортёрами, описанный ниже. Шептать нужно на «Имя Фамилия» без реалма. Свою гильдию клиент видит только по своему ростеру. Доверие к репортёрам и реле задаёт `Config.TRUST_ANY_MEMBER` (сейчас `true`, любой участник). Подробная схема, роли реле и известные дыры — в `docs/DETAILS.md` («Как это работает», «Ограничения»).

**Импорт `/ги`.** Настоящий `CHAT_MSG_GUILD` сразу показывается локально в A с исходными автором, классом и гильдией; штатная строка гильдии остаётся. Только существующий репортёр `Census` с сертификатом передаёт её другим гильдиям после подтверждения связи. Ни локальное событие вместе с сетевой доставкой, ни повторы пакета не должны давать вторую строку A. Без сертификата, готового соединения или обновлённого репортёра локальный A работает, удалённой доставки нет и пропущенные строки задним числом не досылаются; `/chillzone bridge` показывает состояние. Автор без аддона не подписывает текст: получатель доверяет выбранному подтверждённому репортёру о факте сообщения. `CHAT_MSG_OFFICER`, C/L и старые копии с началом `[Чиллзон] ` или `[Мост Чиллзон] ` не импортируются. Импорт добавляется в историю и окно без локального вывода через `Chat.Show`. Прямые A сохраняют настройку локальных копий во вкладках чата игры, но `GuildChat.Mirror` и публикация A через `SendChatMessage(..., "GUILD")` отключены: ни `/cz1`, ни импорт не создают сообщений в обычном `/ги`.

**Совместимость.** Изменение формата в `Codec.lua` или сообщений `Security.lua` (S1, K*) ломает обмен со старыми версиями у игроков. Если формат меняется, это нужно явно отметить в PR и в описании релиза.

Импорт использует только `BH~2~`, `BM~2~`, `BT~2~`: старое приветствие чернового моста не активирует связь, обе стороны должны обновиться. M1/R1/S1 этой правкой не меняются; номер версии не повышается.

Локальный импорт, включая сообщения авторов без аддона, работает без связного, учитывает `chatOn` и игнор; класс сохраняется при доступном GUID или ростере. Обход `Chat.Show` относится к автоматическому выводу при получении: явная команда истории может вывести импортированные строки во вкладки игры. Запрет обратных GUILD-копий действует на обновлённый клиент; старым клиентам он не запрещает отправку, только исключает их копии из импорта. `/chillzone bridge` у читателя показывает выбранного связного, готовность соединений — на клиенте репортёра.

## Правила, которые проверяют тесты и игра

- Только Lua 5.1: без `goto` и меток. UTF-8 без BOM. Файл начинается с комментария или с `local ADDON, ns = ...` (`tests/test_static.lua`).
- В строках, которые видит игрок, допустимы только ASCII, кириллица и символы `«`, `»`, `—`, `№`. Остального (`·`, `…`, `–`, `→`, `×`) в шрифте игры нет, вместо них рисуются квадраты. Тест проверяет все строковые литералы в коде аддона, в комментариях можно что угодно. Тексты интерфейса лежат в `Locale.lua` (`L.KEY`).
- Режим наложения — только через `SetBlendMode`. Второй аргумент `SetNormalTexture`/`SetCheckedTexture`/… игра молча теряет.
- Taint: `ChatPane.lua` не трогает поле ввода и окна чата игры. Список запретов — в шапке файла. `Chat.lua` не перехватывает ввод игрового поля, не пишет его текст, атрибуты и методы и не переводит фокус при наборе `/cz`. Если нарушить эти границы, игра может заблокировать следующий `/cast` или `/target` игрока; после изменения работы с игровым вводом нужна проверка в игре.
- Новый вызов API игры нужно добавить в `read_globals` в `.luacheckrc`, а если код выполняется в тестах — ещё и заглушку в `Env` в `tests/wow.lua`.
- `Chillzone/libs/` — сторонние библиотеки (LibStub, CallbackHandler, HereBeDragons). Их не правим и не линтим.
- `Chillzone/media/` — свои текстуры: несжатые 32-битные TGA с прозрачностью, стороны — степени двойки. `icon.tga` — круглый значок (миникарта, портрет окна), `logo.tga` — логотип целиком (`## IconTexture` в toc). Тест проверяет, что пути из toc и кода ведут на такие файлы.

## Тесты

`tests/lib.lua` — маленький каркас: `T.test`, `T.eq`/`T.ok`/`T.no`/`T.same`, а `T.load(files, env, ns)` грузит файлы аддона в отдельное окружение через `setfenv`. Новый набор тестов нужно вписать в `SUITES` в `tests/run.lua`.

`tests/wow.lua` — симулятор мира. В нём несколько клиентов, у каждого своё окружение и своя копия аддона. Есть гильдии с ростерами, доставка GUILD и WHISPER, общие часы и таймеры. Основное API: `World:Guild`, `World:Client{...}`, `World:Run(seconds)` (двигает часы и запускает таймеры), `Client:Fire`, `Client:Slash`, `Client:Saw(text)`. Так проверяются сценарии переписи, реле и чата целиком.

Для импорта `/ги` проверять две гильдии и нескольких читателей: исходное событие без сертификата/связи сразу даёт локальный A, с готовыми репортёрами строка приходит в A каждой стороны ровно один раз с исходными автором, классом и гильдией. В журнале обычных отправок не должно быть GUILD-копий ни от импорта, ни от прямого A. Отдельно проверять /о и C/L, старые метки копий, старое приветствие, смену репортёра и отсутствие досылки строк после паузы. Заглушка отправки не заменяет проверку на двух игровых клиентах.

То, чего тесты не видят (окно, карта, миникарта), нужно проверить в игре по чек-листу из `docs/DETAILS.md` («Проверка в игре»).

## Olympus

Часть кода портирована из аддона Olympus 1.5.0 (MIT, см. `THIRD_PARTY.md`); шапки файлов говорят, что откуда. Копия Olympus для справки лежит в `reference/olympus-1.5.0/` (не в git) — туда стоит заглянуть, когда нужно понять, как там решена та же задача.
